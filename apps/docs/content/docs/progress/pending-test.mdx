# 待测试

使用临时工作区和测试素材。画布与插件场景分别在纯 Web 和 CLI 检查。

| 场景 | 操作与通过条件 |
| --- | --- |
| 图片详情按内容取宽 | 双击方图、竖图和宽图，确认原图完整显示，两侧仅留栏间距。组内切换时上一张保持到下一张原图就绪；单图省去缩略图栏，窄屏下仍能切图和查看信息。 |
| 删除节点与磁盘回收 | 删除多图节点，检查撤销、重做和手动清理期间原图仍可读取。离开画布或让删除操作退出历史后，检查独占原图、缩略图及自动登记的引用已回收；其他画布、独立素材和聊天引用的图片仍可打开。撤销后保存并退出，再打开应保留整组原图。 |
| 图片生成模型 | 在同一节点用不同渠道或分组生成同名模型的图片，切换详情核对 `模型（渠道-分组）`。改名后查看历史图，并验证单图重试、刷新恢复的结果各自保留提交时的名称。旧图按分组 ID 匹配，无法匹配时显示「渠道 / 分组未记录」。 |
| 拖线引用原图 | 从同一张已有图片的左、右接口分别拖到空白处，选择「图片生成」。两个新节点的输入面板都应显示原图缩略图，连线均从原图指向新节点。 |
| 外部助手生图和主图 | 调整窗口、侧栏和画布缩放，在当前视图创建图片节点，核对初始与完成后整张图片均在屏内。生成期间拖动节点，核对完成后保留新位置。在已有多图节点按图片 ID 设主图，核对目标图置顶、其他图片相对顺序和节点框尺寸。 |
| 本轮占位与完整原图 | 开启保留历史，从已有主图的节点原地生成两张。首张出图前正面显示「生成中」，展开后两个新位置在历史图之前。逐张完成时核对主图，刷新后核对相同顺序。双击打开大横图、大竖图和方图，切换后每张的四条边都在预览区内。 |
| 组内逐张重试 | 同一组留一张成功图和两张失败图。第一张重试期间点第二张，连续点同一张只提交一次。让第二张先完成，第一张随后成功置顶；两张分别写回原槽位，原来的成功图和下次生成张数保留。再分别验证一张失败、主动停止和刷新后查询原任务。 |
| 本地生图结果回显 | 在临时工作区用离线图片模拟已提交的任务，保持面板打开并中断页面对任务的跟踪。确认原图自动回到原节点、成功的图片按完成时间排列，服务只收到原来的生成请求。主动停止、删除槽位或切换画布时核对结果归属。 |
| 详情切图 | 双击图片节点，连续点击横图、竖图缩略图。桌面大图按原始比例显示，最高占窗口高度的 82%，最宽为窗口宽度的 92% 减 330 像素。在矮窗口核对标题、图片四边和关闭按钮均可见。原图读取期间上一张保持可见，窗口位置和大小稳定。核对最后选中的大图、分辨率、主图操作和下载。读取中关闭窗口后，迟到的结果不应重新打开详情。 |
| 本地版偏好与画布视图 | 用原浏览器第一次打开本地工作台，核对已有默认模型、生图张数、保留历史开关、主题和侧栏。移动、缩放两张画布并选择不同背景。退出服务后用另一浏览器打开同一工作区，两张画布分别恢复自己的视图。工作区已有的视图优先。 |
| 提示词和 MCP | 在本地版保存提示词来源、刷新周期并拉取一次。换浏览器后核对来源和缓存。从其他目录运行设置页给出的 MCP 命令，确认连接到所选工作区。加 `--debug` 启动后查看工作区的 `logs/`。 |
| Windows 双击启动 | 双击根目录的 `启动无限画布.bat`，确认浏览器打开端口 17371，数据目录在项目内。保留画布标签页，在启动窗口输入小写 `q` 回车，确认窗口退出。再次双击可重新进入同一工作区。 |
| 连续生图和参考图 | 用同一提示词连续生成两轮，再接入一张参考图生成。核对每轮张数、参考连线、组内历史和主图。全轮失败或刷新恢复后继续查看旧图，并从粘贴或上传的单图重生。关闭保留历史后，确认当前主图参与生成并替换上一批。 |
| 图片详情与排序 | 双击切换缩略图，核对逐图信息和下载原件。手动设主图后该图排第一，其余保持相对顺序。让同批图片先后完成（含重试），每张成功时应排第一并更新下游引用。生成期间手选旧图，再等新图完成，确认新图置顶；刷新恢复的多张结果按实际完成时间排列。 |
| 图片节点尺寸和张数 | 新建图片节点，放大后生成、重试或切主图，确认中心稳定、图片在当前框内保持原始比例。启用自由缩放后保持宽高。设每轮 2 张，删除图组中的一张，再次生图仍请求 2 张。 |
| 源码工作区 | 从仓库启动 CLI 或开发桌面版，确认默认数据目录指向仓库内的 `infinite-canvas-1.0-data/`。显式指定 `--data-dir` 后确认实际路径随之改变。 |
| 让 AI 写单文件插件 | CLI 本地版在「设置 → 插件」点「让 AI 帮我写插件」，把提示词发给 AI 并要求写一个底栏菜单插件：生成的 `client.js` 默认导出只有 `contributions`（及可选 `setup`、`css`），名称说明在 `plugin.json`；点「重新加载本地插件」后能启用，菜单项出现在画布底栏扩展菜单中。 |
| 从 GitHub 安装 Codex 插件 | dev 合并到 main 且 CLI 已发布到 npm 后，在没有本仓库的机器上运行 Codex 插件文档中的两条安装命令：插件显示已安装并启用；新建对话说「打开 Infinite Canvas」，能启动本地服务、打开画布并通过 MCP 读取画布。 |
| 创作页手机端输入框 | 浏览器切到手机宽度（约 375px）打开创作页：输入框底部的创作类型、模型、参数、提示词库、我的资产和发送按钮排在一行，模型名过长时省略显示；创作类型改为下拉选择，切换后对应模型和参数正常；桌面宽度仍显示原来的分段切换。 |
| CLI 重复启动 | 在一个终端运行 `serve --open` 后，另开终端用相同数据目录再次运行：提示已在运行并打开同一地址，不报目录被占用；第一个服务退出后再运行，能正常启动新服务。 |
| CLI 多开页面 | CLI 本地版同时打开 4 个以上工作台页面：每个页面都能正常加载，渠道设置里的赞助商图标立即显示；在一个页面保存作品，其他页面同步更新；外部 Agent 通过 MCP 能读取并操作当前聚焦的画布；停止并重新启动服务后，页面自动恢复连接；源码开发模式下热更新仍正常。 |
